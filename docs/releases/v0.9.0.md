# v0.9.0 — キャンペーンの結果通知・参加体験・費用管理

公開日: 2026-10-27（JST）。X-43〜X-48とUI改善を適用。対応するLINE側の最低版は **L Harness v0.26.0**。

## 変更

更新モーダル、作成準備チェック、詳細条件の折りたたみ、企画名での選択、LINE側で運営者を名前から選ぶ通知設定を追加。

- D1集計による終了時・月曜9:00 JSTの3行通知。LINE運営者、Slack、メールに対応し、既定OFF。任意のGrokが使えない場合はテンプレートを使用。
- 残数・匿名化した参加人数、結果文面、中間ページ（任意）。既定のLINEへの直接転送は維持。
- ハズレ後の明示オプトイン。専用クーポン在庫、同意記録、次回案内のLINE配信下書き。クーポンのみの同意は次回案内の対象にしない。
- 月次・企画別費用見込みと、70%で2倍・90%で4倍の確認間隔。100%で既存の保留処理。推定台帳であり請求上限を保証しない。
- 先着の当選候補だけフォロー・厳格条件・任意のいいねを確認。在庫上限なしと抽選は全員確認。
- 保存しない企画下書きアシスタント。スキーマ・文面・数値・文字数・期間を検証し、利用者がフォームを確認して作成。
- アカウント単位の検索集約は `claim_batch_search=true` のときのみ。既定OFF。512文字ごとの分割、共有カーソル、新規ゲートの追いつき処理。

## 破壊的変更

`requireFollow` は非推奨。`followPolicy` / `likePolicy` を使用する。標準で `verify_winners` を選ぶ場合、`verifyConditionsOptIn=true` が必須。既存 `require_follow=1` は移行時に `verify_winners` へ変換する。先着の確認は候補だけで、在庫切れ後の参加賞・枠外には条件を課さない。再試行が尽きた人は繰り上げの対象となり、条件を後から満たしても在庫は保証されない。

抽選の rank は参加順ではなく確定順のため「確定 #N」と表示する。参加者にX ID入力・Xログインは追加しない。Xへの自動投稿・DMは追加しない。

## 移行とリリース順

DBは021、022を順に適用する。bootstrapとupgrade用SQLは同一。LINE側は既存073以後のテーブルを利用し、新規migrationは不要。新イベントは署名付きcapabilitiesで相手の対応を確認する。

先行X-36bの3点はv0.7.1で公開済みで、この版にも統合済みです。今回の一括公開依頼に合わせ、計画上のv0.8.0分とv0.9.0分をv0.9.0へまとめました。v0.8.0を公開済みとは扱いません。
