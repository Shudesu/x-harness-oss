# Grokなどの外部取得データでキャンペーンを判定する

この機能は、所有者が接続したXコネクタ等から取得した構造化データを使い、対象キャンペーンのX API検索・条件確認・終了時の指標取得を止める任意のモードです。Grokの無料枠・料金・上限はこのソフトウェアでは検証できません。記事・投稿・予約・日次アカウント集計など別機能のAPI呼出しは停止しません。通常投稿をGrokの無料コネクタで公開できることを意味しません。

## 対応する企画と切り替え

- LINE先行・標準ティア・返信だけの条件に対応。アカウント作成日数、専用コード、投稿時刻順、重複防止、在庫確保は既存の判定処理を使用します。
- 厳格ティア、フォロー/いいねのAPI確認、リポスト必須は切り替え不可。有料APIで不足を補いません。
- 所有者が管理画面で企画を一時停止し、取得データによる特典確定とLINE結果通知への影響を確認してから有効化します。照合中の参加や実行中の検索がある間は切り替えできません。
- 再開後、取得した全ページをMCP経由で送ります。既存企画のモードはリリースだけでは変わりません。
- 無料の読み取りで役立つかは利用者のXコネクタで検証してください。代理したデータは所有者からの観測報告であり、Xの署名付き証明や独立した本人認証と表示しません。機密情報・他人の無関係な情報を混ぜないでください。

## Grokに渡す手順

1. Cloudでは `thc_x_gate_sources(tenantId)`、OSS MCPでは `external_gate_sources` で対象と取得方法を確認。CloudのreviewUrl、またはX管理画面で所有者が切り替えます。モードを変更するMCPツールはありません。
2. `thc_x_gate_scan_start(tenantId,gateId)` / `external_gate_scan_start(gateId)` を呼ぶと、検索式・開始終了時刻・必要な投稿/著者フィールド・scanId・page・nextTokenが返ります。
3. 接続済みのXツールを使い、その検索式・時刻範囲で全件を取得します。ツールが条件や著者情報を提供できない場合は停止します。推測・要約・合格/不合格の判断を入力データに代用しません。
4. `thc_x_gate_page_import` / `external_gate_page_import` にepoch/scanId/page/requestToken/nextToken/posts/authorsを渡します。投稿はid,text,author_id,created_at,conversation_id,referenced_tweets,entities。著者はid,username,created_at,protectedと必要に応じてpublic_metricsです。
5. nextTokenは取得元が返したものをそのまま渡します。取得元が終了を示したときだけnullにします。0件の最終ページも送ります。元のAPI応答から必要フィールドを選ぶだけにし、値を作らないでください。
6. 1ページ100件/120KBまで、1スキャン100ページまで。元ページが上限を超える場合は適切な取得件数を指定して最初からやり直してください。勝手にページを分割して完了扱いにしません。
7. 不明な通信結果は同じscanId/page/内容だけを再送できます。異なる内容の再送は409。ページ順、トークン、時刻範囲、必須著者情報を検証し、同時処理はゲート単位で直列化します。

最初の照合だけでは当選を確定しません。全ページ受信後、settle待ち時間の後までカバーする新しいスキャンも完了した時点で、投稿時刻順に原子的に確定します。確定に伴う既存LINE通知は通数を使います。Cloudの取り込みにはread+prepare+executeが必要です。readだけのAIは状態を読むだけです。

## 停止と遅延

検索終了時刻はサーバー時刻の15秒前です。検索反映の遅れを考慮し10分の重複範囲を読みます。X側の検索索引の完全性・順序・到着遅延を保証するものではありません。過去の確定を取り消して再抽選しません。

スキャンは10分で期限切れ。完全受信した検索終了時刻が2分より古い場合や、ページ受信途中は確定を保留します。スキャンのやり直しは最後の完了地点からなので、未完了のページだけで進捗を進めません。未受信期間が6日を超えた場合は手動レビューが必要です。更新が止まっても、未取得の人を不合格にしたり、有料APIへ戻したりしません。状態画面に受信中/停止/データ待ちを表示します。

## 認証・データ

OSSは従来の管理者API認証を使います。Cloudからの専用経路は所有者・許可環境を確認し、既存の環境固有SSO鍵でドメイン分離したHMACを署名します。署名は時刻・HTTPメソッド・パス・本文に紐付き、通常のSSOトークンとして再利用できません。鍵はAIやブラウザへ返しません。変更は所有者セッション+CSRFの画面でのみ提供します。

追加テーブルはgate_external_sourcesとgate_external_receiptsです。既存テーブルを削除せず、モード変更・ページ受信を監査イベントに残します。ページ受信イベントは件数等のみ、参加照合に必要な投稿/著者情報は既存の照合テーブルに保存します。保存と二次利用の同意は別です。
